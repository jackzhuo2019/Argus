## 六、方案的三个差异化立论点

供后续对外表达时收敛叙事使用：

1. **安全边界不靠 Prompt，靠架构（且可证伪）**
   K8s 执行凭据由独立 Broker 持有，Agent 结构性不持真凭据；Higress 管 LLM/MCP 访问平面；K8s RBAC 最小权限；**风险等级由确定性规则查表硬裁定**。即使 Agent 被提示注入完全攻破，破坏上限由 Broker + RBAC + 规则表三层硬约束，且可被红队直接验证（非"靠模型自觉"）。这是多数 AIOps Agent 方案的软肋。

2. **执行者与验证者强制分离**
   Validator 使用独立数据通道，禁止复用 Remediator 提供的任何数据，且无权直接回滚（只能请求）。杜绝「自己批自己卷子」。

3. **风险等级由确定性两阶段管线裁决，不是 Agent 自评、也不是换个 LLM 二审**
   让 Agent（或另一个 LLM）判断「我这个操作危不危险」等于没有安全边界。SK-10 只算爆炸半径数据，最终等级由两阶段管线硬裁定——第一阶段静态规则匹配（action_verb × resource_type × namespace × freeze_window → candidate level + constraints），第二阶段运行时约束校验（检查集群实际状态、未满足则安全升级）。Agent 零覆盖权；未知动作默认拒绝并升级人工。编排控制流同理：Manager 内置确定性模块（OpenClaw 系统指令 + 确定性工具集），LLM 只生成文本，最坏情况是 stall 而非失控。
